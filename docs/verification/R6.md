## Decision and implementation

The user explicitly selected extending the pinned upstream in a local fork. The pin
remains [`codex-chatgpt-web` v6.1.3, `fa2d2c6`](https://github.com/miuuyy/codex-chatgpt-web/tree/fa2d2c6c24926078b46eedb2186f69f2e8d548d7).
[ADR 0002](../adr/0002-r6-local-browser-fork.md) explains the missing upstream contracts,
the fork boundary, persistent authentication and canonical identity.

The vendored subset contains 34 original files: the 31-file browser-worker import
closure, its type declaration, the launcher authentication probe and MIT license.
Three original files are patched; two gateway implementation/type files are added.
`UPSTREAM.json` records original Git blob hashes, exact patch/addition SHA-256 values
and dependency pins. The provenance test verifies these records. Existing R5 pins
and migrations remain unchanged; runtime dependencies are added at the inspected
upstream lock versions. No other private project or runtime is used.

`start --private` now composes the real provider through the existing application
service, request queue, attachment store, persistence and Telegram delivery path.
Browser selectors/types stay inside `providers/chatgpt-web`. Dedicated-profile
ownership, manual `browser:login` and read-only `provider:health` are implemented.
No exported cookies, storage-state credentials or account payloads enter application
configuration, SQLite, diagnostics or test evidence.

`/new` initializes a saved-chat draft without a seed prompt. Its provider key remains
stable when the first user prompt binds the remote URL. `/add` validates an exact
ChatGPT UUID/URL and converges on the same key, including after restart. Generic native
file payloads preserve actual attachment bytes, filename and MIME type.
Upload acknowledgement counts each filename's multiplicity independently within each
UI representation, including distinct files with identical names.

Manual login reuses upstream's normal Chrome launch in that same owned profile, waits
for complete exit and then verifies authentication. It does not export authentication.
Native sessions use upstream's verifier settings for the browser's native keychain.
Owned-child exit, failure and cancellation are covered by offline subprocess tests,
including a child that ignores SIGTERM. Cancellation reuses upstream's existing
five-second graceful wait and bounded SIGKILL path instead of waiting indefinitely.

The physical Send activation is the ambiguity boundary. Missing submission identity,
page loss or persistence failure after activation yields UNKNOWN and is never replayed.
Completion requires the exact operation/turn, no competing user turn, final UI action,
no Stop control and stable content through the upstream tracker. Partial text is not
completion. Capabilities advertise one active conversation and no proven cancellation;
local abort only stops observation. Lost in-memory correlation after restart yields
UNKNOWN. R2–R5 durable acceptance, FIFO, retention and duplicate-update handling remain
on their existing paths.

## Live evidence and remaining limits

The operator explicitly authorized manual login in the dedicated R6 profile and one
new ChatGPT chat with one synthetic prompt/PDF, without live Telegram. Google login
initially stalled at SetSID; opening ChatGPT in another tab showed the signed-in account.
The operator then quit Chrome completely. The first automatic check returned unavailable;
the separate read-only health/restart invocation returned `ready` before and after restart.
This does not establish why the first immediate check was unavailable.

The single authorized roundtrip returned:

```json
{"before":"ready","submission":"submitted","outcome":"completed","answerCharacters":23,"sameCanonicalIdentity":true,"inaccessibleRejected":true,"afterRestart":"ready"}
```

Prompt SHA-256: `6412f5afe5d9ee73caff1bddd726944c8a477fdafc172387417af85c8ff67793`.
Answer SHA-256: `aba37e9044f7aba8f4bf7ba6b4e7030903ce8825ca9bba89ff4aa86633cdae3a`.

The original script exited 1 because `answerMatchesExpected` compared plain text with
upstream Markdown: Turndown escaped exactly three underscores. An offline hash check
confirmed that the complete answer is exactly the expected number and PDF-only marker
with those escapes. The checker now accepts only the exact plain or underscore-escaped
expected string. No second prompt was sent and the revised checker was not rerun live.
The original strict-comparison failure is retained here rather than relabeled as a clean
script exit. Submission, correlated final completion, canonical registration, rejection
of an inaccessible reference and authentication after restart were all observed live.

No live Telegram request was executed. Source/image attachment processing, arbitrary
existing chats, long generations, cancellation and parallel provider mutation were not
exercised live. The live receipt is one bounded scenario, not full MVP acceptance.
R6 exit criteria and overall MVP acceptance remain **pending** until the required
remaining checks and independent review are complete.

The separate `test:live` script checks opt-in before browser/filesystem effects.
`TGWEBGPT_LIVE=1` permits read-only health and restart checks. Roundtrip additionally
requires `TGWEBGPT_LIVE_SEND=1`; it deliberately creates one saved chat and sends one
synthetic prompt plus a valid synthetic PDF. The expected response must include a marker
found only in the PDF. It then checks the same canonical registration, rejects an absent
reference and reopens the owned profile. Receipts contain states, hashes, lengths and
booleans, never full prompts/responses or auth data. Interactive login uses the same
dedicated profile and must be performed by the operator.
