## Clean-install and offline proof

A fresh temporary copy contained the source, tests, documentation, manifest and
lockfile, plus their local configuration files. It contained no `.git`, original
`node_modules`, `.env`, runtime data, browser state or unrelated project files.
The existing user-owned untracked `SPEC.md` was not needed by the copy.

Frozen installation used an independent initially empty package cache and an
environment cleared with `env -i`. The original and copied lockfile hashes were
identical before and after installation and verification:

```text
247a423521ff4a4da91bd3743c545ea531ccf533a8a24b90db8f87a8425650f6
```

After installation, the full `verify` command ran in an additional macOS sandbox
which denied all network operations and reads under the invoking user's home.
The copy, runtime executable and cache were outside that home. The full verification
and all child test processes passed. PATH contained only the temporary Bun executable
directory and `/usr/bin:/bin`; no system Node/fnm installation was available there.

Reproduction outline after preparing a fresh copy and installing the exact runtime:

```sh
# R0_BUN is the absolute Bun 1.4.0 executable.
# R0_RUNTIME_DIR contains that executable; R0_COPY is the fresh copy directory.
cd "$R0_COPY"
env -i PATH="$R0_RUNTIME_DIR:/usr/bin:/bin" \
  BUN_INSTALL_CACHE_DIR="$R0_COPY/.install-cache" \
  "$R0_BUN" install --frozen-lockfile

# Replace the example home path with the invoking user's actual home to deny it.
sandbox-exec -p '(version 1)(allow default)(deny network*)(deny file-read* (subpath "/Users/EXAMPLE"))' \
  env -i PATH="$R0_RUNTIME_DIR:/usr/bin:/bin" \
  BUN_INSTALL_CACHE_DIR="$R0_COPY/.install-cache" \
  "$R0_BUN" run verify
```

The additional sandbox required execution outside the already nested Codex sandbox;
the restricted child profile above was then applied successfully. No source or pins
were changed to obtain the offline pass. Package download was the only step that
required network access.

## Behavioral evidence

- **AC-A01:** `missing config exits with safe field errors before filesystem side effects`
  and the parameterized invalid-config CLI tests prove exit 1, `CONFIG_ERROR`, safe
  issue names/reasons and no new data directory. Token presence and allowlist cases
  are also covered by unit tests.
- **AC-K01:** logging tests check nested secret keys, arrays, recognizable authorization/
  cookie headers and known token values, including encoded URLs. Assertions inspect
  serialized output, not only intermediate objects.
- **AC-K02:** `serializes correlation fields after redaction and discards arbitrary content`
  verifies that prompt, response, config and raw errors are excluded from logs.
- **SQLite safety:** fixtures prove fresh initialization, exactly one application,
  reopen/upgrade preservation, rollback of DDL/data/ledger on fresh and upgraded DBs,
  unchanged applied files, numeric ordering and ledger uniqueness constraints.
- **Connection contract:** foreign keys, WAL, FULL synchronous, 5000 ms busy timeout and
  strict binding were checked on both initial and reopened connections. A real invalid
  foreign-key insert was rejected each time.
- **Bootstrap boundary:** the one-shot CLI test proves success without reporting READY,
  and does not create a browser profile or attachment directory.
- **Environment boundary:** automatic local `.env` loading is disabled; an explicitly
  selected synthetic `.env` works. A changed runtime pin is rejected by a subprocess test.

The manually inspected fresh production database returned:

There are no business or authentication tables. I7 is covered within R0's data/logging

## Repository review

- Existing authoritative specification files were unchanged. README was extended and
  its obsolete specification-only sentence updated.
- No source functionality was deleted; no existing migration was changed.
- New untracked deliverable files were inspected separately because plain `git diff`
  does not include them. `git diff --no-index --check` against `/dev/null` showed no
  whitespace diagnostics; its normal difference exit code 1 was not treated as failure.
- `git status --short --untracked-files=all` was reviewed. Only README and R0 additions
  belong to this task; the original untracked `SPEC.md` was preserved.
- Ignore checks matched `.env`, `.env.local`, default browser/temp data, SQLite database
  and `-wal`/`-shm` sidecars, and node_modules. `.env.example` was correctly not ignored.
- Source, scripts, tests, manifest and lockfile had no upstream/browser/Telegram SDK,
  OpenAI generation client, `file:` dependency or network call. A filename-only scan
  found no token/private-key patterns in authored deliverables.
- No Git staging, commit, branch switch or push was performed. Generated databases and
  clean-copy package cache stayed in temporary storage, outside deliverables.

## Known limits and outstanding decisions

- Validation is on macOS arm64, not a clean physical machine or Linux/Windows.
  Fresh-copy isolation is the demonstrated clean-install scope.
- SQLite is system-dependent on macOS; `3.51.0` is observed evidence, not a new toolchain pin.
- Upstream arbitrary existing-conversation access, provider API/SDK surface, submission
  correlation, attachments and cancellation remain unproven for R6.
- The exact system Node requirement for building the upstream launcher remains
  undocumented; R0 neither needs nor builds that launcher.
- `.agent/rules/memory-bank` and `AGENTS.override.md` are absent. No Memory Bank was
  initialized as part of this scoped bootstrap.
- No blocking R0 decision remains. Contradictory future upstream requirements must
  trigger `R0-D1 DECISION_REQUEST` before changing the approved pins or architecture.
- R1 and later phases were not started; full MVP acceptance was not executed.
